## 一、目标

为 chat-mcp 应用引入"工作目录"概念与"导航侧边栏"，实现：

1. **工作目录**：用户可设置一个文件系统路径作为当前工作目录，该路径决定内置 filesystem MCP server 的可访问根目录。一次只激活一个工作目录。
2. **导航侧边栏**：在功能面板内新增一条可折叠的垂直侧边栏，含两个 tab 导航按钮，在"功能面板"与"工作目录文件树"两个视图间切换。
3. **文件浏览与编辑**：工作目录视图下展示文件树，点击文件可将对话面板切换为该文件的编辑页面。
4. **Git 集成**：如果工作目录已经`git init`，即存在.git，则在工作目录内提供 commit / diff / stage 等 Git 操作。
5. **拖拽创建**：拖拽文件夹到窗口可切换到文件夹所在目录作为新的工作目录。

## 二、用户故事

### US-1 首次启动设置工作目录
> 作为首次使用的用户，我希望应用启动时弹窗引导我选择工作目录，默认填充应用启动目录，以便我快速完成初始化。

### US-2 切换工作目录
> 作为用户，我希望通过侧边栏进入工作目录视图，点击"切换工作目录"按钮选择新路径，切换后 filesystem MCP 的可访问根目录自动更新。

### US-3 重命名工作目录
> 作为用户，我希望对工作目录列表中的项重命名（修改显示名），以便区分多个工作目录。

### US-4 导航侧边栏切换视图
> 作为用户，我希望通过侧边栏的 tab 按钮在"功能面板"和"工作目录文件树"两个视图间切换，侧边栏可折叠以腾出空间。

### US-5 浏览与编辑文件
> 作为用户，我希望在工作目录文件树中点击文件，对话面板切换为该文件的编辑页面，以便查看和编辑文件内容。

### US-6 Git 操作
> 作为用户，我希望在工作目录内（若存在 .git）执行 commit / diff / stage 等 Git 操作。

### US-7 拖拽创建工作目录
> 作为用户，我希望将系统文件夹拖拽到应用窗口，直接以该文件夹路径创建并激活工作目录。

## 三、验收标准

### AC-1 首次启动引导
- [ ] 首次启动（数据库无工作目录记录）时，弹出 Vuetify 对话框（非原生 prompt）
- [ ] 对话框含目录选择控件，默认值为应用启动目录（`app.getAppPath()` 的父目录）
- [ ] 用户确认后创建工作目录记录并激活；取消时使用默认值静默创建
- [ ] 非首次启动不再弹窗

### AC-2 切换工作目录
- [ ] 侧边栏 tab2 激活时，功能面板区显示文件树（工作目录路径标题 + 切换按钮 + 文件列表）
- [ ] 点击"切换工作目录"弹出 Vuetify 目录选择对话框
- [ ] 路径校验通过后，旧 filesystem MCP server 完成在途调用后重建，根路径=新工作目录
- [ ] 切换全程显示 loading 态
- [ ] 若 LLM 流式生成中或 MCP 工具调用中，等待完成后再切换
- [ ] 切换后文件树刷新为新工作目录内容

### AC-3 路径校验
- [ ] Windows：允许 `%USERPROFILE%` 下的目录，或 C 盘以外的盘符路径；拒绝其他
- [ ] Linux/macOS：允许 `~` 目录下的路径；拒绝其他
- [ ] 路径不存在、无读写权限时给出明确错误提示
- [ ] 校验失败时不创建/不切换工作目录

### AC-4 路径失效处理
- [ ] 已激活工作目录的文件系统路径被删除/移动/U 盘拔出时，该工作目录标记为失效
- [ ] 失效工作目录在侧边栏列表中灰显或带"失效"标记
- [ ] 用户点击失效工作目录时提示重新选择路径或取消

### AC-5 重命名
- [ ] 工作目录列表项支持重命名（双击或右键菜单）
- [ ] 显示名允许重名（以 id 区分），路径不可重名

### AC-6 导航侧边栏
- [ ] 侧边栏位于功能面板内：功能面板在右侧时侧边栏在最右侧；功能面板在左侧时侧边栏在最左侧
- [ ] 侧边栏含两个 tab 按钮：tab1=功能面板（默认激活），tab2=工作目录
- [ ] 侧边栏宽度固定（参考标准侧边导航栏宽度），支持折叠/收起
- [ ] tab1 激活：功能面板显示现有功能内容，对话面板显示聊天
- [ ] tab2 激活：功能面板显示文件树

### AC-7 文件编辑
- [ ] 文件树中点击文件 → 对话面板切换为文件编辑页面（tab 内容页机制，聊天内容不丢失，切回 tab1 恢复）
- [ ] 编辑器支持读取文件内容并展示
- [ ] 编辑器支持保存（写入文件系统），保存需遵守 `write_approval` 标志

### AC-8 Git 集成
- [ ] 工作目录存在 `.git` 时，文件树或工具栏显示 Git 操作入口
- [ ] 支持 stage / unstage / commit / diff 查看
- [ ] 无 `.git` 时不显示 Git 入口

### AC-9 拖拽创建
- [ ] 拖拽系统文件夹到应用窗口 → 以该路径创建工作目录并激活
- [ ] 路径校验失败时提示原因，不创建

### AC-10 i18n
- [ ] 所有新增 UI 文案提供中英双语（项目已有 Vue I18n）

### AC-11 数据隔离
- [ ] 会话历史、附件、MCP 服务器列表及启用状态、API Key 与模型选择、技能/工作流、语言设置、`write_approval` 标志、面板列宽偏好均为全局共享，不随工作目录切换
- [ ] 工作目录记录独立存储，不与业务表外键关联

## 五、技术约束

### 5.1 技术栈
- Electron 30 + Vue 3 (UMD) + Vuetify + Pinia（沿用现有）
- 主进程 TypeScript，渲染进程沿用现有 UMD/IIFE 脚本结构
- 数据库：better-sqlite3（主进程侧，单 db 文件）

### 5.2 数据结构
```sql
-- workspaces 表（新增，无外键关联业务表）
CREATE TABLE workspaces (
  id          TEXT PRIMARY KEY,   -- UUID
  name        TEXT NOT NULL,      -- 显示名（允许重名）
  path        TEXT NOT NULL UNIQUE, -- 文件系统绝对路径（唯一）
  created_at  INTEGER NOT NULL,   -- Unix 时间戳
  last_active INTEGER NOT NULL,   -- 最近激活时间，用于排序
  status      TEXT NOT NULL DEFAULT 'active'  -- 'active' | 'invalid'
);
```

### 5.3 持久化
- 工作目录记录存入 better-sqlite3（主进程），通过 IPC 暴露给渲染进程
- 当前激活工作目录 id 存入 localStorage（Pinia 持久化）
- 其余业务数据继续沿用现有 localStorage / sessionStorage 机制，不改动

### 5.4 路径校验规则
| 平台 | 允许范围 | 拒绝 |
|---|---|---|
| Windows | `%USERPROFILE%` 下子目录；C 盘以外盘符任意路径 | C 盘下非 USERPROFILE 路径；系统目录 |
| Linux | `~` 下子目录 | `~` 以外路径；系统目录 |
| macOS | `~` 下子目录 | `~` 以外路径；系统目录 |

校验内容：路径存在、有读写权限、符合平台范围规则。

### 5.5 MCP filesystem 联动
- 切换工作目录时，等待在途 LLM 流式生成和 MCP 工具调用完成
- 重建内置 filesystem MCP server 实例，根路径 = 新工作目录 path
- 重建期间显示 loading 态

### 5.6 侧边栏布局规则
- 功能面板在右侧（`functionPanelCols` 在右）→ 侧边栏位于功能面板最右侧
- 功能面板在左侧（swap 后）→ 侧边栏位于功能面板最左侧
- 侧边栏随功能面板位置变化而镜像

### 5.7 i18n
- 新增文案 key 统一加入现有 i18n 资源文件，提供 `zh` / `en` 两套
